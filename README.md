Система управления контентом и публикациями на нативном PHP с использованием PDO и реляционной СУБД MySQL. Включает клиентскую часть, личный кабинет с разделением прав по ролям и изолированную панель управления.



## 1. Системные требования
* PHP: версия 8.0 или выше (обязательно расширение `pdo_mysql`)
* СУБД: MySQL 8.0+ / MariaDB 10.4+
* Веб-сервер: Apache с поддержкой `mod_rewrite` или Nginx + PHP-FPM



## 2. Развертывание и установка
1. Разместите проект в рабочей директории веб-сервера.
2. Предоставьте веб-серверу права на запись в каталог загрузки медиафайлов:
```bash
chmod 775 uploads

```


3. Создайте рабочую базу данных:
```sql
CREATE DATABASE blog_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

```


4. Настройте параметры подключения к СУБД в конфигурационном файле `includes/db.php`:
```php
$host = 'localhost';
$dbname = 'blog_db';
$username = 'root';
$password = 'root';

```


5. Для локальной проверки запустите встроенный веб-сервер PHP:
```bash
php -S localhost:8000

```

## 3. Схема базы данных

| Таблица | Назначение | Поля, типы данных и ключи |
| --- | --- | --- |
| `users` | Учетные записи | `id` (INT, PK, AUTO_INCREMENT), `username` (VARCHAR, UNIQUE), `password` (VARCHAR, Bcrypt-хэш), `role` (VARCHAR, default 'user') |
| `news` | Публикации контента | `id` (INT, PK, AUTO_INCREMENT), `title` (VARCHAR), `content` (TEXT), `image` (VARCHAR), `author_id` (INT, FK -> users.id), `created_at` (DATETIME) |
| `contacts` | Сообщения обратной связи | `id` (INT, PK, AUTO_INCREMENT), `name` (VARCHAR), `email` (VARCHAR), `message` (TEXT), `submitted_at` (DATETIME), `processed` (TINYINT(1), default 0) |
| `subscriptions` | Реестр подписчиков | `id` (INT, PK, AUTO_INCREMENT), `name` (VARCHAR), `email` (VARCHAR, UNIQUE), `created_at` (DATETIME) |

## 4. Архитектура и реализация

### Аутентификация и контроль сессий

* **Хранение учетных данных:** Пароли не сохраняются в открытом виде; используется алгоритм Bcrypt через `password_hash($password, PASSWORD_DEFAULT)`. Верификация выполняется функцией `password_verify()`.
* **Защита от инъекций:** Все операции взаимодействия с базой данных реализованы через параметризованные запросы PDO (`PDO::prepare`) с типизированной привязкой данных.
* **Сессионный контроль:** Авторизованное состояние сохраняется в суперглобальном массиве `$_SESSION` (`user_id`, `username`, `role`). Завершение сеанса производится функцией `session_destroy()` в скрипте `logout.php`.

### Ролевая модель доступа (RBAC)

* `user`: Доступ к базовой части сайта, просмотр публикаций, добавление новостей, отправка сообщений и подписок.
* `admin`: Полный административный доступ. В интерфейсе личного кабинета динамически отображается кнопка перехода в административную часть. Доступ к каталогу `admin/` защищен серверной проверкой (`$_SESSION['role'] === 'admin'`); при нехватке прав запрос принудительно перенаправляется на `login.php`.



### Основные модули системы

* **Публикация контента (`post.php`):** Редактирование текста через интеграцию CKEditor 5. Загрузка обложек публикаций сопровождается серверной проверкой, переименованием по Unix Timestamp во избежание коллизий и сохранением в директорию `uploads/`. На клиенте реализован предпросмотр изображения через `FileReader API`.


* **Модерация обратной связи (`admin/fos.php`):** Постраничный вывод входящих сообщений (по 10 записей на страницу, вычисление смещения `OFFSET` на уровне SQL). Переключение статуса обработки (`processed`) выполнено по шаблону Post/Redirect/Get (PRG) для предотвращения повторной отправки данных при перезагрузке страницы.
* **Служба подписок (`subscribe_handler.php`):** Асинхронный обработчик входящих заявок. Обработка дублирующихся адресов e-mail реализована на уровне СУБД с помощью запроса `INSERT ... ON DUPLICATE KEY UPDATE`.
